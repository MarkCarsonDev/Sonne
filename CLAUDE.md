# Sonne — project guide for Claude

Sonne is a minimalist static site generator (~5k LOC Python): Markdown +
Jinja2 templating, a blog pipeline (tags/categories/RSS), and an image
pipeline (resize, format conversion, dithering). Python >= 3.9. Windows is a
first-class platform — never assume POSIX paths or separators.

## Commands

```bash
pip install -e ".[dev]"       # setup
pytest                        # full suite (unit + integration)
pytest tests/unit             # fast tests only
ruff check . && ruff format --check .   # lint / format
sonne new -p <dir> -t blog && (cd <dir> && sonne build && sonne serve)
```

## Architecture

Build pipeline: `cli/commands.py` → `core/site_generator.py` (orchestrator)
→ `core/config.py` (DEFAULT_CONFIG + YAML/JSON site config, deep-merged)
→ `core/variable_manager.py` (data files, `scripts/*.py` data scripts,
variable scopes: global → site → page) → `processors/`
(`template_processor.py` Jinja2+Markdown, `blog_processor.py`
posts/taxonomies/RSS, `image_processor.py` resize/dither/cache).
Shared helpers in `sonne/utils/`. Bundled site templates in
`sonne/templates/{blog,minimal,portfolio,solar}` (copied by `sonne new`);
config JSON schema in `sonne/schemas/sonne.schema.json`; core static assets
(dithering CSS/JS) in `sonne/static/`.

## Hard rules

- **Version** is single-sourced in `sonne/__init__.py`. Never hardcode a
  version string anywhere else (this bug has happened; don't reintroduce it).
- **Config keys change in lockstep**: `DEFAULT_CONFIG` (config.py) +
  `sonne/schemas/sonne.schema.json` + `README.md` + `CHANGELOG.md`, always
  together. A key that exists in only one of those places is a bug.
- **Renames of config keys** go through `sonne/core/deprecations.py`
  (old→new mapping, warn once per key). Never silently drop an old key.
- **Logging**: library code uses `logging.getLogger('sonne')`, never
  `print()`. CLI-only output may use rich/click.echo with plain fallbacks.
- **Config access** via `config.get('section', 'key', default=...)` — do not
  reach into `config.config` directly.
- **One slugify**: `sonne/utils/text.py::slugify` is canonical. Never add a
  second slug implementation (three divergent ones once caused taxonomy 404s).
- **Paths**: compare/route by path components (`pathlib`, `os.path.relpath`),
  never `str.startswith` on path strings or `lstrip('./')` (both caused real
  bugs). Everything must work with both `/` and `\`.
- **`scripts/*.py` are trusted by design** — they execute with full process
  privileges at build time. Document, don't sandbox; never silently expand
  what gets executed.
- Behavior changes require a CHANGELOG entry; breaking changes need a
  deprecation path (pre-1.0 exceptions get an explicit "Changed" entry).

## Testing workflow

- The suite is a **characterization suite**: it pins current behavior.
  Refactors must keep it green; intentional behavior changes update the
  pinned test in the same commit with a CHANGELOG note.
- Known-bug fixes are staged as `@pytest.mark.xfail(strict=True, reason="Bxx: ...")`
  tests asserting the FIXED behavior; the fixing commit removes the marker.
  strict=True means an accidental early fix fails the suite — deliberate.
- Fixture sites live in `tests/fixtures/`; test images are generated by
  Pillow in `conftest.py` (`make_image`) — never commit binary images.
- Google-style docstrings; broad `except Exception: logger.error(...)` is
  the house error idiom but must always log, never `pass`.
